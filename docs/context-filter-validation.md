用户选择了 **Patch 15.18**，但 Brand 在这个版本只有 **8 场比赛**，少于最小要求的 **10 场**。

系统行为：

3. 返回基础后验 P₀

5. **无论如何切换，都显示相同的基础值**

## 为什么调整幅度这么小？

### 原因 1：Brand 的位置分布非常稳定

Brand 在不同补丁版本的位置分布变化很小：
- 全局：jungle 97.1%, support 2.9%
- 14.14：jungle 97.8%, support 2.2%（差异 < 1%）
- 14.15：jungle 91.7%, support 8.3%（差异较大）

### 原因 2：平滑常数 ε = 3 的作用

权重计算公式：
```
w = (freq_patch + 3) / (freq_global + 3)
```

平滑常数防止小样本产生极端权重。例如：
- 如果 freq_patch = 0.92, freq_global = 0.97
- w = (0.92 + 3) / (0.97 + 3) = 3.92 / 3.97 ≈ 0.987
- 调整幅度被压缩

### 原因 3：调整应用在频率上，不是后验上

- patch-region-stats.json 存储的是**观察频率**（jungle 97.1%）
- bayesian-role-posteriors.json 存储的是**后验概率**（jungle 75.4%）
- 调整应用在后验上，但权重来自频率比率

**关键问题**：
- 频率从 97.1% → 91.7%（变化 5.4%）
- 但权重只有 0.9863（变化 1.4%）
- 应用到后验后，75.4% → 74.9%（变化 0.5%）

## 结论

### Context Filter 功能状态

| 组件 | 状态 | 说明 |
|------|------|------|
| UI 组件 | ✓ 正常 | ContextFilter.tsx 正确渲染 |
| 状态管理 | ✓ 正常 | selectedPatch/selectedRegion 正确传递 |
| API 路由 | ✓ 正常 | /api/role-flexibility 正确响应 |
| 数据文件 | ✓ 正常 | patch-region-stats.json 存在且有效 |
| 调整逻辑 | ✓ 正常 | adjustRolePosterior() 正确计算 |
| **样本量** | **⚠ 问题** | **大多数补丁版本样本 < 10** |
| **调整幅度** | **⚠ 小** | **通常 ±0.5-1%，不明显** |

### 用户体验问题

1. **选择了样本不足的补丁**：用户测试 15.18，但只有 8 场比赛
2. **调整幅度太小**：即使有足够样本，调整通常 < 1%，肉眼难以察觉
3. **缺少反馈**：UI 没有显示"样本不足"的警告

## 建议的改进

### 短期修复（立即可做）

1. **在 UI 中显示样本量警告**
   - 当样本 < 10 时，显示 "⚠ 数据不足（< 10 场）"
   - 禁用或灰显样本不足的选项

2. **推荐有效的补丁版本**
   - 在下拉菜单中标记有效版本（如 "14.14 ✓"）
   - 默认选择样本最多的版本

3. **显示调整幅度**
   - 在位置分布旁边显示变化（如 "75.4% → 74.9% (-0.5%)"）
   - 用颜色标记增加/减少

### 中期改进（需要数据更新）

1. **降低最小样本量阈值**
   - 从 10 场降低到 5 场
   - 但增加不确定性标记

2. **收集更多数据**
   - 扩大数据源，增加样本量
   - 特别是新补丁版本

3. **改进权重计算**
   - 调整平滑常数 ε（从 3 降低到 1）
   - 使调整更敏感

### 长期优化（架构改进）

1. **预计算所有调整**
   - 在构建时预计算所有英雄 × 补丁 × 赛区组合
   - 客户端直接加载预计算结果

2. **增量数据加载**
   - 只加载当前选择的补丁/赛区数据
   - 减少初始加载时间

3. **实时数据更新**
   - 连接到 Riot API 或数据源
   - 自动更新最新补丁数据

## 测试指南

### 如何验证 Context Filter 工作

1. **选择有效的补丁版本**：
   - ✓ 14.12, 14.13, 14.14, 14.15, 14.16, 14.17
   - ✗ 避免 15.x 版本（大多数样本不足）

2. **观察细微变化**：
   - 调整幅度通常 ±0.5-1%
   - 需要仔细观察百分比数字
   - 不要期望 10% 以上的变化

3. **检查浏览器控制台**：
   - 打开 DevTools → Network
   - 查看 /api/role-flexibility 请求
   - 检查 adjustmentMeta.notes 字段

4. **测试不同英雄**：
   - 选择 flex 英雄（如 Sylas, Swain）
   - 这些英雄的调整可能更明显

## 总结

**Context Filter 功能本身是正常的**，但存在两个用户体验问题：

1. **数据覆盖不足**：许多补丁版本样本 < 10，导致调整被拒绝
2. **调整幅度太小**：即使有足够样本，变化通常 < 1%，不明显

**建议**：
- 在 UI 中显示样本量和调整幅度
- 推荐有效的补丁版本
- 考虑降低最小样本量阈值或调整平滑常数
