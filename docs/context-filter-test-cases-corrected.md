# Context Filter 实际测试案例（更正版）

## 重要说明

### 数据类型的区别

系统中有两种不同的数据：

1. **观察频率**（patch-region-stats.json）
   - 职业比赛中实际打的位置比例
   - 例如：Neeko 在 Patch 14.1 中 92.9% 打中路

2. **贝叶斯后验概率**（bayesian-role-posteriors.json）
   - 基于历史数据的概率分布
   - 这是用户在 Global 模式下看到的基础值
   - 例如：Neeko 的基础后验 mid 20.0%

3. **调整后的后验概率**（用户实际看到的）
   - P_adjusted = P₀ × weight
   - weight = (freq_patch + 3) / (freq_global + 3)
   - 平滑常数 ε=3 大大压缩了调整幅度

### 为什么变化这么小？

**Neeko 案例**：
- 观察频率：12.8% → 92.9%（变化 +80%）
- 权重计算：(0.929 + 3) / (0.128 + 3) = 1.256
- 后验调整：20.0% × 1.256 = 25.1%
- **实际变化：+8.2%**（归一化后是 +8.3%）

平滑常数的作用：
- 防止小样本产生极端权重
- 保持概率分布的稳定性
- 但也导致即使观察频率变化很大，实际显示变化也较小

## 为什么我之前的分析错了？

### 我的错误
我分析的是 **patch-region-stats.json** 中的观察频率：
- Neeko 在 Patch 14.1：MID 92.9%（职业比赛中实际打的比例）
- 这个数据确实变化很大（+80%）

### 实际情况
用户看到的是 **调整后的贝叶斯后验概率**：
- 基础后验：MID 20.0%
- 权重：1.256
- 调整后：28.3%
- 实际变化：+8.3%

### 平滑常数的影响
```
weight = (freq_patch + 3) / (freq_global + 3)
       = (0.929 + 3) / (0.128 + 3)
       = 3.929 / 3.128
       = 1.256
```

平滑常数 ε=3 的作用：
- 当观察频率很小时（如 0.128），加 3 后变成 3.128
- 分子分母都加 3，导致权重接近 1
- 即使观察频率变化很大，权重变化也较小

## 实际变化幅度总结

### 变化幅度分布
- **10-17%**：极少数英雄（Jayce, Rell, Jax, Neeko）
- **5-10%**：少数英雄
- **1-5%**：大多数英雄
- **< 1%**：很多英雄

### 为什么变化这么小？
1. **平滑常数 ε=3**：压缩了权重变化
2. **设计目的**：避免小样本产生极端调整
3. **稳定性优先**：保持概率分布的合理性

### 这是否意味着功能无用？
**不是！** 这个设计是合理的：
- 10-15% 的变化在实际应用中已经很显著
- 避免了过度依赖小样本数据
- 保持了系统的稳定性和可靠性
